# Flujo GitHub (equipo de 4)

- `main`: versión estable para demostración.
- `develop`: integración continua; proteger si el equipo tiene permisos.
- `feat/HACK-XX-nombre`: una tarea acotada por rama.
- Cada PR: objetivo, datos de prueba, evidencia de ejecución, riesgos y revisiones.
- Nunca subir secretos ni CSV nacionales pesados.
- Proponer un integrador (también encargado de documentar) y dos desarrolladores responsables de pipeline + app. Cuarta persona: investigación, validación y demo.
- Tablero: Backlog, Ready, In progress, Review, Done.
- Integrar temprano: un PR pequeño es mejor que un merge masivo el domingo.

## Antigravity
Abrir la carpeta raíz del repositorio. Entregarle una tarea a la vez, indicando archivos permitidos, criterio de aceptación, pruebas y prohibición de editar otros módulos. Revisar los diffs antes de aprobar.
